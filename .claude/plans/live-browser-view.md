# Live browser view (/browser)

## Context
Sean wants to watch Chromium fill forms, and log in to LinkedIn/AllJobs/JobMaster by hand, from the dashboard at autojob.sean.build (Cloudflare tunnel to 127.0.0.1:8040), from a desktop or phone browser. Half of it is already in the worktree, uncommitted: `autojob/browser/display.py` (Xvfb + x11vnc + websockify, pid files in `data/vnc/`), `browser_page(..., visible=True)`, the `login.py` rewrite, `get_browser_visible_mode`, the `/browser` sidebar mapping, `apply.py` wiring, vendored noVNC 1.6 core under `autojob/web/static/novnc/` (LICENSE.txt and VENDORED.txt present).
Missing: the page, the authenticated WebSocket, the toggle, tests. Nothing here imports or picks anything from outside the app: the three login sites are fixed buttons, no URL or ID fields.

## Design

### Decisions
1. **Drop websockify; the FastAPI route relays bytes straight to x11vnc's TCP port.** noVNC speaks RFB over binary WebSocket frames and offers no subprotocol by default, so `/browser/ws` is a ~30 line `asyncio.open_connection("127.0.0.1", x11vnc_port)` relay. One fewer process, pid file and port, and the `websockify` dependency (which dragged numpy into uv.lock) goes away. Stack becomes: Chromium (headed) draws on Xvfb `:99` (`-nolisten tcp`), x11vnc serves RFB on `127.0.0.1:5999` (`-localhost`, password file), FastAPI proxies.
2. **The `browser_visible_mode` toggle lives on `/browser`**, next to the view it affects, not on Targets.
3. **Visible mode starts the display stack itself, and falls back to headless if it cannot.** `apply.py` gets `_visible_mode(conn, config, run_id) -> bool`: returns False when the setting is off; otherwise calls `display.start_all(config)` and returns True, or on `DisplayStackError` emits an `apply`/`error` event `Browser view unavailable (<reason>); running headless` (silent when `run_id is None`) and returns False. An apply never fails because x11vnc is missing.
4. **`login.py` keeps the managed-display path (no `xvfb-run` fallback).** The old helper ran headed under xvfb-run on a display nobody could see, so a hand login was never possible there; the managed display is the same virtual framebuffer, now watchable. Behaviour kept: missing binary prints an `apt-get` hint and returns 1, 10 minute cap, exits when Sean closes the window, Ctrl+C keeps the session. The `/browser` page gets the "Log in to ..." buttons the new docstring already promises, since SSH is the only alternative.
5. **Status is rendered at page load**; noVNC's own connect/disconnect events drive the live status line. Start/Stop/Save/Login reload the page. No polling.

### display.py (after Task 1)
`DisplayConfig`: drop `novnc_port`, `websockify_pid_path`, `websockify_log_path`, `DEFAULT_NOVNC_PORT`, `AUTOJOB_NOVNC_PORT`. `status()` returns `{"xvfb", "x11vnc", "all_running", "display", "x11vnc_port"}`. New: `missing_binaries() -> list[str]` (`shutil.which` over `XVFB_BIN`, `X11VNC_BIN`), `_missing_binary_error(binary) -> DisplayStackError` (the apt hint, used by `_spawn` and by new `_store_vnc_password(display_config, password)`, which wraps the `-storepasswd` `subprocess.run` and turns `FileNotFoundError` into that error). Everything else as written: pid files, idempotent `start_all`, `stop_all` in reverse order, `main`.

### context.py
When `visible`, also pass `args=["--window-position=0,0", f"--window-size={w},{h}"]` with `w,h` parsed from `load_display_config(config).geometry` (`1366x900x24`), so the Chromium window fills the Xvfb screen (there is no window manager).

### Routes (`autojob/web/routes.py`, section `# --- browser view ---`, before `# --- profile and CV`)
- `GET /browser`: context = `base_context` plus `stack` (`display.status`), `missing` (`display.missing_binaries()`), `visible_mode` (`get_browser_visible_mode`), `vnc_password` (`display.ensure_vnc_password(load_display_config(config))` only when `stack.all_running`, else None), `login_site` (`app.state.login_site` when `app.state.login_thread` is alive, else None), `notice` (`app.state.browser_notice`, read then cleared), `flash` from query (`saved=1` -> "Saved.", `login=started` -> "Login window opening in the view below.", `busy=1` -> "A login window is already open.").
- `POST /browser/start` (csrf): `display.start_all`; on `DisplayStackError` set `app.state.browser_notice = str(exc)`. Redirect 303 `/browser`.
- `POST /browser/stop` (csrf): `display.stop_all`, redirect `/browser`.
- `POST /browser/settings` (csrf, `browser_visible_mode: bool = Form(False)`): `db.set_setting(conn, "browser_visible_mode", value)`, redirect `/browser?saved=1`.
- `POST /browser/login/{site}` (csrf): 404 unless `site in LOGIN_URLS`; `?busy=1` if `app.state.login_thread` is alive; else `display.start_all` (failure -> notice, redirect); then `threading.Thread(target=_run_login_session_in_background, args=(app, config, site), daemon=True)` which calls `login.run_login_session(config, site)` and on any exception stores `f"Login window failed: {exc}"` in `app.state.browser_notice`; set `app.state.login_site`, redirect `/browser?login=started`.
- `@router.websocket("/browser/ws")`: `RequireLoginMiddleware` never sees websocket scopes, `SessionMiddleware` does, so the route checks itself before accepting: `websocket.session.get("logged_in")` else `close(code=1008)` (uvicorn answers the upgrade with HTTP 403); if an `Origin` header is present and `urlparse(origin).netloc != headers["host"]`, `close(1008)`. Port from `load_display_config(websocket.app.state.config).x11vnc_port` (no `Depends(get_config)`: it is typed for `Request`). `reader, writer = await _open_vnc_connection("127.0.0.1", port)` (module-level wrapper around `asyncio.open_connection`, so tests can fake it); `OSError` -> `close(1011)`. Then `accept()` (no subprotocol), two tasks: ws->tcp (`receive_bytes`, `writer.write` + `drain`; `WebSocketDisconnect` ends it) and tcp->ws (`reader.read(65536)` until empty, `send_bytes`); `asyncio.wait(FIRST_COMPLETED)`, cancel the other, `writer.close()`, best-effort `websocket.close()`.
- `app.py` `create_app`: `app.state.browser_notice = None`, `app.state.login_thread = None`, `app.state.login_site = None`. `PUBLIC_PATHS` unchanged.

### Page (`autojob/web/templates/browser.html`, extends base.html; sidebar link `Browser` after `Live`, active when `active_section == 'browser'`)
Order, all in `.card`s: (1) flash/notice line; (2) **Virtual display**: chips `Xvfb` and `x11vnc`, `chip chip-sent` text `up` / `chip chip-failed` text `down`; buttons `Start display` (hidden when all running) and `Stop display` (hidden when nothing runs); when `missing` is non-empty, one `field-hint` per binary: `x11vnc is not installed on the server. Install it with: <code>sudo apt-get install -y x11vnc</code>, then press Start display.` (3) **Live view**: when `stack.all_running`, `<div id="browser-screen" class="browser-screen"></div>`, a `<p id="browser-status" class="field-hint">Connecting…</p>`, a `<button type="button" id="browser-reconnect">Reconnect</button>`, and `<script type="module">` that does `import RFB from "/static/novnc/core/rfb.js"`, builds `url = (location.protocol === "https:" ? "wss://" : "ws://") + location.host + "/browser/ws"`, `new RFB(screen, url, { credentials: { password: {{ vnc_password | tojson }} } })`, `rfb.scaleViewport = true`, `rfb.resizeSession = false`, listeners `connect` -> `Connected.`, `disconnect` -> `Disconnected. Press Reconnect.`, `securityfailure` -> `VNC password rejected.`; Reconnect disconnects and creates a new RFB. When not running: `Start the display to watch the browser here.` If `login_site`: `Login window open for <site>. It closes itself after 10 minutes, or when you close the tab in the view.` (4) **Log in to a site**: three forms `Log in to LinkedIn` / `AllJobs` / `JobMaster` posting to `/browser/login/<site>`, hint `Opens the site's login page in the live view for up to 10 minutes. Log in by hand; the session is saved for every later scan and apply.` (5) **Apply runs**: form to `/browser/settings`, `checkbox-label` `Show apply runs in the live view`, hint `When on, Apply now, Release and the scheduled apply phase open Chromium on this display instead of headless, so you can watch forms get filled. Scans stay headless. The display starts itself when needed; if it cannot, the run falls back to headless.`, `Save` button.
Visual spec (`style.css`, appended): `.browser-screen { width: 100%; aspect-ratio: 1366 / 900; background: #0E1111; border: 1px solid var(--card-border); border-radius: 12px; overflow: hidden; }`. No CDN: the only new script URL is `/static/novnc/core/rfb.js` (its relative imports resolve under `/static/novnc/core/`).
Fresh account: display stopped, both chips down, Start button (or the install hint), login buttons, toggle off. Nothing is hidden by an empty state.

## Verification on the phone or desktop (https://autojob.sean.build/browser)
1. Before `sudo apt-get install -y x11vnc`: the Virtual display card shows both chips down and the install hint; Start display shows the same hint as a notice, nothing crashes.
2. After installing: Start display turns both chips up and the Live view shows a dark canvas with `Connected.`
3. Press `Log in to LinkedIn`: within a few seconds a Chromium window with the LinkedIn login page appears in the view. From a desktop browser, click into it and type; log in; close the tab. The view returns to the bare display. (Phone: taps work as clicks; typing needs a desktop or a hardware keyboard in this build.)
4. Tick `Show apply runs in the live view`, Save, then Apply now on a queued job with auto_submit off: Chromium appears and fills the form in the view; the application lands `ready_to_submit` as before.
5. Untick and Save, Apply now again: nothing appears in the view, the application is still filled.
6. In a private window, `/browser` redirects to `/login`; the Run log shows no error for the normal headless scan.
7. Stop display: both chips down, the Live view card says to start the display.

## Risks
- Keyboard mapping through x11vnc can mangle some keys; if typed characters come out wrong, add `-xkb` to the x11vnc argv in `_start_x11vnc`.
- Clicking inside the view while an apply run is filling a form interferes with the handler; the hint under the toggle says watch, not steer.
- A login window holds the browser lock for up to 10 minutes; a scheduled apply in that window hits the existing `BrowserBusyError` path and the job is requeued.
- The Cloudflare tunnel passes WebSockets but may drop a long-idle one; the Reconnect button covers it.
- The VNC password is rendered into the authenticated page; it only guards a `127.0.0.1` port that x11vnc already refuses from elsewhere.
- Chromium on a bare Xvfb has no window manager: no decorations, window at 0,0; closing the last tab is how the login session ends early.
